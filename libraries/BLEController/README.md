# BLEController

Raw H4 byte interface for the BL616CL external-host Controller; status: **experimental**. Requires `bl616cl-libs` 0.5.0 together with the matching platform. The BL device runs neither ArduinoBLE, NimBLE, nor another BLE Host. HCI over AT for RA4M1 ArduinoBLE on UNO R4 WiFi remains an application responsibility and is not implemented by this library.

`BLEController.begin()` allocates transport resources and starts the Controller. After success, the external Host must still send HCI Reset and initialization commands and check their events. `write(data, size)` returns the number of bytes accepted; after a short write, the Host must retain and resend the remainder. `available()`, `read()`, and `read(data, size)` expose H4 events/ACL from the Controller. After the Host has stopped transfers and disconnected, `end()` stops the Controller and releases transport resources; a subsequent `begin()` is supported. All public calls must be serialized in one application task. This interface supports one Host. Logs must not be mixed into the command stream.

H4 parsing retains the upstream UART HCI engine, connected to FreeRTOS byte streams through the UART completion callbacks in the matching headers. It uses no physical UART or pins. The transport task has priority 30 and the Controller task priority 29 (with the current 32 priority levels), ensuring that the upstream ISR completion callback registers its deferred job before the Controller is scheduled. The initial reversed priorities caused HCI Reset to receive no response on real hardware. Wi-Fi and BLE share one radio initialization. Each direction has a 1024-byte buffer; the Host must observe the HCI packet lengths and flow control reported by the Controller. The tested LE configuration reported an ACL length of 251 and 4 transmit buffers.

See `examples/ControllerUSB` for the raw USB example. The dependency package manifest records the source, matching headers/libraries, and configuration: upstream `libbtblecontroller_bl616cl_uarthci.a`, SDK release v2.3.38 (commit `946f92a07af31a3fb66da75675b539289037fcc0`), original archive SHA-256 `5334e1af3d73b4d88cd1678520049ab5a594100afa7069f44fc707febeb265f3` (built by upstream with GCC 14.3.0). The library string of the earlier 1cd1fd51 archive was 1.6.212 and has not been re-read for this one; upstream `btble_controller_get_lib_ver()` actually returns the text `NULL`, so version/capability acceptance uses real HCI queries rather than a wrapper around that function. The SDK root Apache-2.0 text is included in the package; complete product redistribution review remains under ARDUINO-54.
