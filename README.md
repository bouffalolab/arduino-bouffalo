# arduino-bl

Generic Bouffalo Arduino platform, starting with BL616CL and intended to expand to additional chips over time.

Current stage: an initial local candidate. Individual platform/bridge feature acceptance and ARDUINO-52–55 release gates are complete; final release approval remains reserved. The Core and first board support arduino-cli compilation, image generation, and upload through onboard USB. `Serial` is USB serial; `Serial1` and `Serial2` are hardware UARTs.

The intended user workflow is installation through Boards Manager / Arduino CLI followed by compilation and upload without the full Bouffalo SDK. An independent builder publishes the underlying dependencies.

The current platform requires `bl616cl-libs` 0.9.0 and `bl-flash-tools` 0.2.0 (IPv4 IGMP multicast and matching netif ABI, retaining SNTP, DHCP hostname, IPv6, hidden AP, littlefs, and HID/BLE). Update the platform and dependency packages together.

Public user documentation: [Start here](docs/README.md), [Installation](docs/INSTALL.md), [Support and acceptance scope](docs/SUPPORT.md), [Recovery](docs/RECOVERY.md), and [License notices](docs/LICENSING.md). These files are versioned with the platform and included in its archive.

Compilation and upload depend on three tools: `bl616cl-libs`, `bl-flash-tools` (both generated by `arduino-bl-lib-builder`), and Xuantie GCC V2.6.1. The platform references them through `runtime.tools.bl616cl-libs.path`, `runtime.tools.bl-flash-tools.path`, and `runtime.tools.xuantie-gcc-riscv.path`. Without package-index installation, local tests supply these using `--build-property` for compilation and `--upload-property` for upload.

## Images and upload

After compilation, `bflb_fw_post_proc` updates the boot header in `<sketch>.ino.bin` in place and generates `partition.bin` in the build directory. Upload uses `BLFlashCommand` to write packaged boot2, the partition table, and firmware at 0x0, 0xE000, and 0x10000 respectively. Addresses and capacities are fixed by build-directory `layout.json`/`layout.toml`. It verifies SHA-256 after writing and starts the new firmware with a warm reset. On UNO R4 WiFi, BL616CL uploads through onboard USB; select the running sketch's USB serial port (`349b:0011`):

```sh
arduino-cli upload -b bouffalolab:bl:unor4wifi_bl616cl -p <serial-port> --input-dir <build-directory> <sketch>
```

Upload follows Arduino 1200 bps touch: arduino-cli opens and closes this port at 1200 baud; the Core sets a request to enter download mode after reset and issues a power-on reset. ROM exposes a USB download serial port (`ffff:ffff`), and arduino-cli waits for it before flashing. On new firmware startup, the Core clears the request so later software resets boot normally. `Serial.setTouchReset(false)` disables touch when the application handles 1200 baud itself, as the bridge does. In that case, call `resetToBootloader()` from the sketch or enter download mode manually as described below.

If installed firmware lacks this Core, is hung, or does not enumerate USB, first enter download mode manually by holding bootstrap GPIO36 high during reset. Run the same upload command against the ROM download port; after waiting about 10 s for a new port, arduino-cli reuses that port.

Limits:

- Tools currently support Linux x86_64 only. Upload runs a FlashCommand copy under build-directory `flash-runner/`; installed tools may be read-only.
- Images omit the DWARF CFI table appended by native SDK builds, so crash `backtrace` reports 0 frames.
- The dts uses SDK development-board factory parameters (crystal and RF); parameters for the replacement module remain unconfirmed.

## Local build checks

Optional raw HID shares a single USB initialization with CDC. Without registration, only CDC enumerates; registration adds interface 2 and interrupt IN/OUT endpoints. Applications read/write HID from tasks; Feature callbacks execute in USB interrupts and must not block. Report semantics and target-chip control belong to the application. The Core contains no CMSIS-DAP or RA4M1 logic.

Linux raw HID requires device permissions. The platform supplies `tools/99-arduino-bl.rules` for USB/hidraw VID:PID `349b:0011` only. Install into `/etc/udev/rules.d/`, reload rules, and reconnect the device. Rules use `plugdev` and `uaccess`. This hardware round used a temporary ACL on current device nodes without changing permanent system rules.

```sh
tests/compile_check.sh <bl616cl-libs-package-directory> <Xuantie-GCC-directory> <bl-flash-tools-directory> [paths-to-hide...]
```

Platform configuration is also checked with official Arduino [arduino-lint](https://arduino.github.io/arduino-lint/); strict mode should report no errors:

```sh
arduino-lint --project-type platform --compliance strict .
```

The script copies the platform into a temporary sketchbook, uses bubblewrap to replace supplied paths (SDK checkout/build directories, etc.) with empty directories, and compiles every sketch under `tests/sketches/`. `tests/check_map.py` checks that the Wi-Fi group is not linked, `_malloc_r` comes from the SDK libc port, and `main` comes from the Core. `tests/check_image.py` verifies a written boot header and existing `partition.bin`. Requires `arduino-cli`, `bwrap`, and `python3`; arduino-cli downloads built-in tools such as ctags/discovery afresh into temporary directories each time, requiring network access.

## WiFi modes and independent interface configuration (ARDUINO-49)

Generic networking lives in `libraries/WiFi` without bridge or RA4M1 dependencies. Ordinary `begin` / `beginAP` still switch STA/AP; explicit `WiFi.mode(WIFI_AP_STA)` allows coexistence. `mode(WIFI_OFF)` stops both interfaces; `disconnect(true)` removes only STA, and `softAPdisconnect(true)` removes only AP. Without true, connections stop but interface selection remains. Once initialized, the protocol stack is not deinitialized.

`config` retains Arduino's behavior of configuring both interfaces. Use `configSTA(ip, dns, gateway, mask)` and `softAPConfig(ip, gateway, mask)` for independent configuration. AP currently supports only /24. Online AP address changes restart DHCP, requiring clients to renew/reconnect. In mode3, `localIP/subnetMask/gatewayIP/SSID` return STA values; `stationIP/stationSubnetMask/stationGatewayIP` always query STA, and `softAPIP/softAPSSID` always query AP.

`beginAP(ssid, pass, channel, hidden, maxConnections)` supports hidden SSIDs and association limits. Default 5 matches the pinned official bridge, but pinned wl80211 has only 4 association slots, so effective capacity is at most 4, without a 5-client concurrency guarantee. `setAutoReconnect` defaults to true and becomes active only after this begin successfully acquires an IP. Unexpected disconnections trigger background retries; initial failure does not reconnect to an old network, and explicit disconnect suppresses retries. Policy and credentials reside only in RAM.

`enableIpV6()` enables STA link-local; `localIPv6()` returns its string or `::` without a valid address. It does not extend existing IPv4 `IPAddress` or TCP/UDP APIs and promises neither global IPv6 nor DHCPv6. Update the underlying 0.7.0 IPv6 ABI, headers, and libraries as a set. This task's records define new feature status and hardware acceptance boundaries. Connection limits require real simultaneous associations; compilation or a single client is not proof.

## SNTP and DHCP hostname (ARDUINO-45)

`WiFi.getTime()` immediately returns UTC Unix seconds, or 0 before year 2000/synchronization, without waiting for networking. Initial WiFi setup automatically configures `pool.ntp.org`; acquiring a STA IP triggers asynchronous SNTP. After synchronization, time continues offline and reconnection requests synchronization again. `WiFi.configTime(server)` asynchronously changes the server; null, empty, or over-253-byte names return false. Changing only the server does not clear synchronized time.

`WiFi.getHostname()` / `WiFi.setHostname(name)` use RAM. The default is `bl616cl-` followed by the STA MAC's final 3 bytes in uppercase hexadecimal. Names are 1..31-byte ASCII DNS labels: letters, digits, and hyphens, without leading/trailing hyphens. Invalid values return false and preserve the old value. Online changes do not disconnect; later DHCP requests carry the new name, and reset restores the default. This provides neither DNS/mDNS services nor Flash persistence.

Underlying 0.8.0 enables `LWIP_NETIF_HOSTNAME` and compiles SDK SNTP; headers, libraries, and configuration require coordinated updates. Newlib UTC advances through the system microsecond timer; pinned patches correct the SDK RTC-alarm misuse and onboard RC32K drift. Deep-sleep timekeeping and retention across power loss are not promised. SNTP does not change the existing TLS policy of skipping certificate date checks. See `libraries/WiFi/examples/WiFiTime`; hardware acceptance is recorded independently in ARDUINO-45.

## IPv4 UDP multicast (ARDUINO-50)

`WiFiUDP::beginMulticast(group, port)` accepts IPv4 multicast addresses starting with 224..239 and nonzero ports, binds any local address, and joins through lwIP. Invalid input or join failure returns 0. Underlying protocol restrictions remain: for example, 224.0.0.1 is the implicitly joined all-hosts group and cannot be explicitly joined through this interface. Closing sockets through `stop()`, destruction, or a new `begin()` lets lwIP leave groups and reclaim buffers. UDP uses `SO_REUSEADDR` so several groups can share a local port.

`beginMulticastPacket()` selects the joined group address/port. The added `beginPacket()` extension reuses the most recently explicitly selected destination or the source of the last successfully parsed `parsePacket()` datagram. New/reopened sockets have no destination and return 0. Both begin methods only prepare transmission; `write` and `endPacket` are still required. RX/TX remain limited to 1460 bytes per datagram. `remoteIP/remotePort` retain this platform's current received-datagram source semantics, unlike the pinned ESP32 implementation that also updates remote queries after explicit TX destination selection.

Version 0.9.0 enables `LWIP_IGMP=1` with an IGMP pool of `2 * MEMP_NUM_NETCONN + 2 = 18`. Pinned wl80211 creates both STA/AP netifs; a join through either consumes one entry on each, plus all-hosts entries. Generic socket capacity remains 8 and bridge UDP capacity remains 4; there is no additional membership table. Headers and libraries must be updated together. Multicast depends on actual AP forwarding/IGMP behavior and UDP does not promise reliable delivery. This does not add IPv6 UDP or cross-channel STA/AP support. See `libraries/WiFi/examples/WiFiMulticast`.
